## 标题
重构 `settings.ts`：registry 声明 + 统一 getConfig + 门面函数三层模式

## 背景
当前 `settings.ts` 每个配置项都内联手写一遍 `env || db || default`，加配置要改四处（type、getSetting、默认值、优先级合并），加密字段还要每个函数手动 `decryptIfAvailable`。需要收敛为统一配置层，同时**保证调用方零改动**。

## 前置修复（先做，与重构解耦）
1. **敏感字段空值回写问题**：定时任务设置页，敏感信息（`cron.secret`、`cron.job_api_key`）首次配置正确，再次保存时因不回显导致前端提交空字符串，后端把 DB 值覆盖为空。
   - 修复：后端保存时，若提交值为空字符串且该字段标记为敏感，**跳过更新**（保留原值），而不是写入空串。
2. **手动触发扫描按钮禁用问题**：定时任务管理页「手动触发一次扫描」目前依赖 cron 配置存在才可点，实际手动触发不需要 cron 配置。
   - 修复：手动触发按钮的禁用条件改为**只依赖其自身必需的配置**，去掉对 `cron` 配置的依赖。

## 重构目标
将 `settings.ts` 从「每个配置项内联读取」改为三层：

```
层 3 门面函数（签名不变，内部调 getConfig）
层 2 getConfig（唯一优先级合并点 + 解密 + transform）
层 1 registry（配置声明，加配置只加一行）
层 0 settings 表读写（完全不动）
```

## 硬性约束（Invariants）

### 层 0 不动
以下函数实现与签名**一字不改**：
`getSetting`、`setSetting`、`deleteSetting`、`setSettingsBatch`、`getAllSettings`。

type ConfigDef<T> = {

const registry = { /* ... */ } satisfies Record<string, ConfigDef<any>>;

### 层 2 getConfig
```ts
export async function getConfig<K extends keyof typeof registry>(
  name: K,
): Promise<(typeof registry)[K]["default"]>
```

执行顺序：
1. `def = registry[name]`
2. `dbVal = await getSetting<string>(def.key)`
3. 若 `def.secret && dbVal` → 动态 `await import("@/lib/crypto")` 取 `decryptIfAvailable` 解密给 `dbResolved`；否则 `dbResolved = dbVal`
4. `envVal = def.env ? process.env[def.env] : undefined`
5. `raw = envVal || dbResolved || def.default`（优先级：env > db > default）
6. `return def.transform ? def.transform(String(raw)) : raw`

### 层 3 门面函数
保留以下导出，**签名与返回类型不变**，内部改为 `Promise.all` 并行调 `getConfig`：
- `getSiteSettings(): Promise<SiteSettings>` + `type SiteSettings`
- `getSocialLinks(): Promise<SocialLinks>` + `type SocialLinks`
- `getFooterSettings(): Promise<FooterSettings>` + `type FooterSettings`
- `getAboutContent(): Promise<string>`
- `setAboutContent(content): Promise<void>`（实现不变）
- `getGiscusConfig(): Promise<GiscusConfig>` + `type GiscusConfig`
- `getCronConfig(): Promise<CronConfig>` + `type CronConfig`

特殊行为保留：
- `getFooterSettings`：`copyright` 为空时用 `new Date().getFullYear()` 生成 `© {year} 林圣轩blog. All rights reserved.`，判定用 `||`。
- `getCronConfig`：`deployPlatform` 归一化由 registry 的 `transform` 负责，门面函数不再处理。

### 导入依赖
- 保留：`eq`、`db`、`settings`
- `@/lib/crypto` 的 `decryptIfAvailable` 改为 `getConfig` 内部**动态 import**，不在顶部静态导入（避免循环依赖）
