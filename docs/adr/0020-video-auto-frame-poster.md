# ADR 0020：视频未设封面时自动截取首帧作为封面

- 状态：Implemented（2026-10-03）
- 关联：视频相册上传链路 / 编辑弹窗
- 实现：`components/videos/capture-frame.ts` +
  `video-upload-dialog.tsx`（上传自动截帧）+ `video-edit-dialog.tsx`（「从视频生成封面」按钮）+
  `app/api/admin/videos/route.ts`（multipart / presign 回调透传 `posterMediaId`）

## 背景

视频前台卡片依赖封面图撑起瀑布流比例（`aspect-ratio: width / height`）。此前封面只能手动上传：
视频上传成功但无封面时，前台卡片显示占位图，需要用户回到编辑弹窗再传一次封面，体验断裂。

## 方案对比

| 方案                  | 说明                                                              | 结论                                                             |
| --------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------- |
| A. 服务端 FFmpeg 截帧 | 上传后在服务端抽帧，产物质量最可控                                | 否决：Vercel Serverless 无 FFmpeg 环境，引入转码服务超出现有架构 |
| B. 前端 canvas 截帧   | 浏览器加载视频 → seek 首帧 → canvas 输出 JPEG，走现有图片上传链路 | 采纳：零新增依赖、复用 `media/VIDEO_POSTER` 链路，成本最低       |
| C. 不上封面           | 保持现状                                                          | 否决：前台体验差                                                 |

## 决策

1. **前端截帧**：上传探测视频信息后，用隐藏 `<video>` 加载源（本地 Blob 或远程 URL），
   seek 到 0.1s（不超过时长 90%），canvas 按原始分辨率输出 JPEG（0.85 质量）；
2. **复用现有封面链路**：截帧结果作为 `VIDEO_POSTER` 类型走 `POST /api/admin/media` 入库，
   拿到 `media.id` 后随视频回调/上传请求携带 `posterMediaId`；
3. **失败静默降级**：截帧任何一步失败（文件损坏、编码不支持、CORS 污染、超时 20s）
   都返回 null，视频继续无封面上传，不阻塞主流程；
4. **编辑弹窗补生成**：封面区新增「从视频生成封面」按钮，
   对已上传的旧视频（或当时截帧失败的视频）可随时补生成封面。

## 影响与限制

- **CORS 依赖**：对远程 URL（S3 直链）截帧依赖存储桶放行 GET + 干净 CORS，
  否则 canvas 被污染、`toBlob` 失败 → 静默降级为无封面（部署文档已含 CORS 配置说明）；
- **截图质量**：封面内容取决于视频首帧画面，不保证构图；
  用户不满意可手动上传替换，替换逻辑沿用 ADR 0019（旧封面不级联删，交给清理流程）；
- **与 ADR 0019 的关系**：自动截帧同样产生 `VIDEO_POSTER` 孤儿可能
  （截帧成功但回调落库失败——media 记录存在但 video 未引用），
  由「孤儿封面清理」入口统一回收，本 ADR 不新增回收逻辑。
