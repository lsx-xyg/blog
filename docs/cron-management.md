# 后台定时任务管理（cron-job.org）使用说明

> 状态：已上线（2026-09-16，cron 系列 #19-#23 完成）
> 相关：docs/adr/0006-cron-backup.md（双实现决策）、docs/adr/0009（备份/元数据/Cron UI）
> 需求：#19 执行历史、#20 通知设置、#21 HTTP 基本认证、#22 文件夹、#23 响应保存查看

## 1. 概览

后台定时任务管理页（`/[adminSlug]/cron`，组件 `ManageCron` + `ManageCronJobs`）用于管理 cron-job.org 外部定时任务：

| 能力 | 说明 |
|---|---|
| 全局定时发布 | 创建/启停站点定时发布扫描任务（每分钟执行，扫描到期文章自动发布） |
| 任务管理 | 任务列表 CRUD、启用/禁用、高级配置（调度/请求头体/认证/通知/文件夹） |
| 执行历史 | 历史列表 + 单次详情（状态/HTTP 码/时长/性能统计） |
| 响应查看 | saveResponses 开启的任务可查看响应头与响应体（JSON 格式化/超长截断） |
| 文件夹 | 文件夹侧边栏筛选 + 增删改管理（删除时任务移到根目录） |

## 2. API 配额约束（重要）

**当前使用 cron-job.org 免费版：每日 100 次 API 请求**（每请求各计 1 次，含本页所有查询与操作）。设计原则：

1. **页面打开零请求**：不自动加载任何状态，由用户点击按钮按需加载
2. **一按钮一 API**：加载状态 / 加载任务列表 / 加载文件夹各自独立按钮，互不连带
3. **刷新全部**：需要全量刷新时一次性触发（当前 3 个 API：状态 + 任务 + 文件夹）
4. **操作后按需刷新**：全局启停后只刷状态；任务增删改后只刷任务列表，不连带其他请求

**一次操作的 API 消耗参考**：打开页面 0 次；点「加载状态」1 次；点「加载任务列表」1 次；点「刷新全部」3 次；创建/编辑任务 1 次；启停 1 次；打开历史弹窗 1 次；点单条详情 1 次；响应查看 0 次（随详情返回）。

## 3. API 清单（全部需管理员 session，前缀 /api/admin/cron）

| 方法 | 路径 | 说明 | 对应 lib/cron 函数 |
|---|---|---|---|
| GET | /cron | 总览状态（平台/密钥配置/全局任务/接口地址） | — |
| POST | /cron/start | 启动全局定时发布（存在则复用，不存在则创建） | findGlobalPublishJob / createGlobalPublishJob |
| POST | /cron/stop | 停止全局定时发布（**当前实现为删除任务**，见 §5） | findGlobalPublishJob / deleteCronJob |
| POST | /cron/run | 手动触发一次定时发布扫描 | — |
| GET | /cron/jobs | 任务列表 | listCronJobs |
| POST | /cron/jobs | 创建任务（url 必填） | createCronJob |
| GET | /cron/jobs/[id] | 任务详情（含 auth/notification/extendedData） | getCronJob |
| PATCH | /cron/jobs/[id] | 更新任务（部分字段） | updateCronJob |
| DELETE | /cron/jobs/[id] | 删除任务 | deleteCronJob |
| GET | /cron/jobs/[id]/history | 执行历史列表 | getJobHistory |
| GET | /cron/jobs/[id]/history/[identifier] | 单次执行详情（响应头/体/性能统计） | getJobHistoryDetail |
| GET | /cron/folders | 文件夹列表 | listCronFolders |
| POST | /cron/folders | 创建文件夹（name 必填） | createCronFolder |
| PATCH | /cron/folders/[id] | 重命名/启用禁用文件夹 | updateCronFolder |
| DELETE | /cron/folders/[id] | 删除文件夹（任务移根目录） | deleteCronFolder |

## 4. 页面操作指南

### 4.1 加载控制条（页面顶部）

页面打开显示「数据尚未加载」提示条，含三个按钮：**加载状态 / 加载任务列表 / 加载文件夹**（各自 1 个 API）+ **刷新全部**（3 个 API）。已加载的数据区块不再重复显示对应按钮。

### 4.2 全局定时发布（当前实现）

「全局定时发布」区块展示全局发布任务运行状态（运行中/未运行、下次执行、任务 ID）+ 启动/停止/手动触发按钮。**该区块与任务列表存在重复展示**（全局任务也是 cron-job.org 任务之一），重构方向见 §5。

### 4.3 文件夹侧边栏 + 任务列表

- 左侧：全部任务 / 未分类 / 各文件夹（含任务数），点击筛选任务列表
- 右侧：任务列表（标题/方法/URL/下次执行/上次执行），行内操作：执行历史 / 启用禁用 / 编辑 / 删除
- 「设置」图标打开文件夹管理弹窗：新建 / 重命名 / 删除（删除前确认，任务移到根目录）

### 4.4 任务表单分区

| 分区 | 内容 |
|---|---|
| 基本信息 | 标题、请求 URL（必填）、请求方法、超时、启用/保存响应/3xx 视为成功 |
| 所在文件夹 | 下拉选择（根目录未分类 / 各文件夹） |
| 调度配置 | 时区 + 分/时/日/月/周（`-1`=每、逗号分隔多值） |
| 通知设置 | 折叠：失败/成功/自动禁用/SSL 过期 4 开关 + 失败次数 + SSL 提前秒数 |
| 高级配置 | 折叠：请求头（键值对动态增删）、请求体、HTTP 基本认证（开关+用户名+密码） |

编辑任务时先取详情回填（headers/body/auth/notification/文件夹），**编辑打开即消耗 1 个 API**。

### 4.5 执行历史与响应

- 任务行「历史」按钮 → 弹窗加载历史列表（1 个 API）：状态徽章（OK/请求失败/超时/SSL 无效等 8 种）、执行时间、时长、URL
- 点击单条 → 加载详情（1 个 API）：HTTP 状态码、计划/实际执行、抖动、有效 URL、性能统计（DNS/连接/SSL/首字节/总时长）
- 任务开启「保存响应」且有数据时出现「查看响应」按钮 → 弹窗展示响应头 + 响应体（JSON 美化 / 原样，超 100,000 字符截断，含敏感信息提醒）

## 5. 已知问题与重构方向（探讨中，未实施）

1. **全局定时发布语义**：当前 `stop` 是**直接删除** cron-job.org 任务（`deleteCronJob`），删除后执行历史随之丢失。更合理语义：启动/停止 = PATCH `enabled` true/false（保留任务与历史），仅在显式「删除」时真正移除。
2. **区块重复**：「全局定时发布」区块与任务列表展示同一任务。方向：改为**系统定时任务预设配置列表**（如定时发布扫描），预设驱动创建 CRON；任务列表中的系统任务打「系统」徽章区分。系统任务可能不止一个（发布/备份/清理等），命名与区块结构待确认。
3. 免费配额下 `run`（手动触发）为跨系统操作：触发的是站点接口而非 cron-job.org API，但会立即执行一次扫描。

## 6. 部署与环境

- VERCEL 模式需配置：`CRON_SECRET`（接口鉴权）、`CRON_JOB_API_KEY`（cron-job.org API Key，设置页可配）、`NEXT_PUBLIC_SITE_URL`
- SERVER 模式：node-cron 内置，应用启动即运行，无需手动启停（见 ADR-0006）
- 免费版配额：cron-job.org 账号设置页可查剩余用量；接近上限时避免频繁「刷新全部」
